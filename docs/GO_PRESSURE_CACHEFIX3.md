# cachefix.3 新增 Go API 原生压力长测

2026-10-20。测试源码固定于 [24b2bc8](https://github.com/ad64001/dsh-conversation-memory/commit/24b2bc8d5945577c996bdf491795753f3bb9b083)；实际成功压缩 **10/10**，状态 **completed**。完整公开概要见 [go-pressure-cachefix3-summary.json](../validation/go-pressure-cachefix3-summary.json)。

## 真实运行口径

使用运行中的 DSH 0.2.1-rc.2 原生 Agent 和自动 Basic 压缩。在独立会话中，以可撤销且按会话过滤的绑定加载发布版 cachefix.3 bridge、工具声明/执行器，并在独立原生预设中加载其 semantic-pruner。桌面其他会话仍使用原安装版本；本轮没有替换桌面插件文件，也没有重启应用。测试前已核验真实 request/header 中 search/index 的查询上限为1000，Go响应成功、模型和会话头正确，主请求预算不变。

原生窗口配置1,000,000，压力阈值550,464，尾部预算98,560，headroom65,536，主请求输出预算384,000；未降低阈值、手工压缩或伪造事件。合成源码通过正常用户输入填充，避免超大工具输出的spill只保留预览。被测Agent仅有四个原生memory工具，无法读取控制器或golden答案；搜索不启动子Agent。源码填充方式也意味着本长测不构成大型工具结果语义裁剪的全面质量验证。

## 记忆与运行边界

随机项目/身份/canary/失败原因来自初始用户原文。周期2纠正参数，周期4加入条件授权，周期6撤销，周期8重新授权。提问不含正确答案；逐轮检查真实search/read、引用→SQLite来源→原生用户事件、码点范围和SHA256。初始原生用户事件是否移出surface与是否仍有完整副本另外记录。摘要本身仍可能保留事实，正确答案和已验证回读不能证明答案只依赖归档。

严格答案值通过9/10；字段注记归一化后匹配10/10。这项补充核对是在第8轮出现字段内[n]引用后新增的事后复核，只移除已验证读到的引用后缀和明确的(reissued)注记；原严格失败保持不变，不把格式核对改称首次通过，也未重发API补答案。
第8轮另有解释措辞歧义：独立historicalFailureCause字段正确写出签名过期，但conditionReason把“更新签名解决问题”写得像失败归因。补充字段匹配不是整段自然语言保真的证明。
按独立原生持久化日志重新投影的154份预期文本来源，与SQLite的154份记录逐字匹配=true。该口径排除隐藏reasoning、派生快照和自身记忆工具返回，不声称所有原生事件类型都应入库。
所有引用都另有当轮memory_read调用覆盖：8/10；将当轮search中已实际提供、经SQLite引用原文及哈希验证的完整正文计入，正文供给覆盖：10/10。引用定位符不算正文。该核对不证明模型注意力或每条引用与每个断言的语义相关性。
正常续轮保留此前完整wire消息前缀：20/20。这证明所测前缀稳定性；服务端缓存驻留仍由托管服务决定。
自动召回被动观测66次，其中incomplete=66，压缩维护pending=66；最后状态见JSON。高负载下的未完成状态不能当作自动整理成功，即使显式回读通过。
usage未知请求ID：6,7,36。无服务端usage的传输/服务错误不记作零token成功；SDK内部重试次数与相应计费可能未知。首尝试与首成功分开，不能把重试隐藏成首次成功。
独立原生zstd日志与观察器压缩事件核对一致：true。公开概要保留事件位置、原文回读判断和源码哈希，原始日志留在本机；没有上传真实用户会话或凭据。
本轮没有记录服务端内容过滤阻断。

预检单列，不混入上述正式KV统计：初次会话的桥接core为cachefix.3，但工具schema仍来自旧宿主，停止后补齐按会话的声明和执行器绑定；另一次本地工具声明含函数，被原生request/header校验拒绝，没有Go请求。之后新建正式会话并通过真实请求头与响应核验。预检的已报告usage和未知用量另列于JSON。

本结果是有限单机、单服务运行，不是严格A/B提升幅度、固定KV保证或零遗忘保证。尤其不能把约99%的正常续轮当作压缩后首请求或所有辅助调用的命中率。高负载自动召回的未完成状态仍需单独评估。
