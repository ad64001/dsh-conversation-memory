# 普通短续轮的缓存验收

在 Windows DSH 0.2.1-rc.5 的原生 Agent 上，用 OpenCode Go 的 DeepSeek V4.1 Flash、`max` 推理和桌面端工具集复核仓库发布证据。每个长测都在独立目录和会话库中运行，由 DSH 的 `compactNow` 连续压缩同一会话三次。测试驱动提交用户问题并记录事件，记忆工具由模型自行选择。

## 最终安装版结果

三个独立会话中，**14 / 14 个普通短续轮逐轮达到 95%**。共读取 423,808 个缓存 token，总提示为 428,046 个 token，加权命中率 **99.01%**，最低单轮 **95.86%**。全部 14 轮都有可核验的服务商用量。[逐请求明细](../validation/short-followups-0.6.1.csv) · [分类统计和历次诊断](../validation/short-followups-0.6.1.json)

| 最终版会话 | 用户回合 | 原生压缩 | 短续轮通过数 | 单轮最低 | 短续轮加权 | 压缩后首请求加权 | 全部请求加权 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 交付口径复测 | 8 | 3 | 3 / 3 | 96.90% | 97.75% | 60.92% | 71.85% |
| 独立短追问 | 5 | 0 | 4 / 4 | 99.55% | 99.64% | — | 90.25% |
| 隔离发布评审 | 12 | 3 | 7 / 7 | 95.86% | 98.64% | 60.09% | 67.60% |

隔离评审有 24 个随机登记码。抽到的 RC-23 签核码没有出现在任何一份压缩摘要或签核回合的首个主请求中。模型先查工作区材料，随后自行调用 `memory_search`，首次收到正确值，再用 `memory_read` 核对原文。模型填对了 12 位签核码、从 91.4% 修订为 96.8% 的任务阈值，以及缺失用量单列、不得填零的规则。隔离会话的 7 个短续轮依次为 99.75%、95.86%、98.05%、97.38%、98.79%、98.13%、98.82%。

Windows DSH 0.2.1-rc.5、0.2.2-rc.5 和 0.2.3-alpha.2 各通过 378 项回归测试。

## 逐轮如何计数

每个新用户输入按 Unicode 码点计数，长度最多 128 的续问取首个主请求。会话的首请求、原生压缩后的首请求、同一用户回合内的后续工具步骤和辅助调用都另行登记。放行要求是每个纳入的请求至少 95%。另报加权值，计算方式为总缓存读取 token 除以总提示 token。DSH 的总提示 token 由未命中输入、缓存读取和缓存写入三项相加。缺少可核验用量的请求单列。实测没有发送预热请求。

## 修复过程

| 实验 | 达到 95% 的短续轮 | 加权命中率 | 最低单轮 |
| --- | ---: | ---: | ---: |
| 0.6.0，原长任务 | 0 / 3 | 65.61% | 51.65% |
| 调整路由头及初版证据复用条件 | 0 / 8 | 88.24% | 75.02% |
| 加入已完成回答检查点，复跑原长任务 | 3 / 3 | 98.32% | 98.00% |
| 检查点候选版，扩展发布评审 | 8 / 8 | 99.01% | 98.36% |

后续专门测试了一条 60 字的验收口径纠正。旧处理会再发送历史证据，服务商记录为 11,392 / 13,590，即 83.83%。最终版直接接收用户新原话，再跑同一条纠正时为 11,392 / 11,756，即 96.90%。两次的分子都是缓存读取 token。

早期诊断允许模型访问评审目录的上级，其中有会话读到了测试计划。表中保留这些真实调用的用量。独立的记忆验收采用隔离目录和进程内随机签核码，读取权限限定在四份评审材料及当前会话的记忆。测试未向模型指定检索时机、工具或查询词。

## 0.6.1 怎样处理续轮

普通短追问可以沿用已进入上下文的证据，当前用户原话照常入库。模型可以主动搜索和回读其他记录。压缩、模型切换和待处理的维护工作仍会触发检索。插件为 OpenCode Go 的同一会话提供一致的路由头。[OpenCode 路由实现](https://github.com/anomalyco/opencode/blob/dev/packages/core/src/session/model-request.ts)

在此次验证的 Go 路由上，新用户消息到达后，插件可将已结束的纯文本助手回答投影为本地助手检查点。检查点保留可见回答原文及助手角色。DSH 会话中保留完整响应。工具调用和结果、当前回合推理、带不透明签名的内容及其他模型继续使用原生回放。这样可避免把上一答的大段推理再次计入本轮未命中输入。可用 `cachePolicy: legacy` 选择原有回放和检索策略。

DeepSeek 的工具调用协议要求原样回传参与工具链的推理，缓存命中由服务商报告。部署记录所列百分比适用于实际测量的路由和请求。[DeepSeek 推理协议](https://api-docs.deepseek.com/guides/thinking_mode/) · [服务端上下文缓存](https://api-docs.deepseek.com/guides/kv_cache/)

## 复核公式

在仓库根目录运行以下 Python 代码，可从逐请求 CSV 复算最终安装版的逐轮通过数、最低值和加权命中率。

```python
import csv

with open("validation/short-followups-0.6.1.csv", encoding="utf-8") as source:
    rows = [r for r in csv.DictReader(source)
            if r["run"] in {"installed-final", "installed-short", "sealed"}
            and r["category"] == "ordinary-short"]
assert all(r["prompt"] and r["cacheRead"] for r in rows)
ratios = [int(r["cacheRead"]) / int(r["prompt"]) for r in rows]
weighted = sum(int(r["cacheRead"]) for r in rows) / sum(int(r["prompt"]) for r in rows)
print(sum(r >= 0.95 for r in ratios), len(rows), f"{min(ratios):.2%}", f"{weighted:.2%}")
```
