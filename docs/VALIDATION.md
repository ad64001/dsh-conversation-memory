# 验证与边界

## 0.6.0 连续压缩后的碎片回读

在 Windows DSH 0.2.1-rc.5 上，用同一个原生 Session 连续调用三次手动压缩。每次都由 DSH Basic 构建摘要提示、计量、写入压缩事件并替换上下文；通过本机 llama.cpp 的回环接口生成摘要，模型为 Qwen3-4B-Instruct-2507 Q4_K_M。使用合成会话和独立 SQLite 库。测试程序驱动工具调用。联想读取在 CPU 上运行，环境为 Python 3.14.6、PyTorch 2.13.0、NumPy 2.5.2、ONNX Runtime 1.31.1 和 tokenizers 0.22.2。

Windows 0.2.1-rc.5、0.2.2-rc.5、0.2.3-alpha.2 分别通过 376 项回归，含本地安装、登记、会话读写和回滚。三轮真实模型压缩运行于 0.2.1-rc.5。

- 草案将并行数设为 128，验收版改为 64。按条件或目标查询后检查数值、来源角色及原话。第二轮之后关闭并重新打开插件的记忆工作进程。
- 每轮加入一份合成装配记录，抽取其中一条部件编号。检查原文事件和抽查编号均已离开当前上下文，然后查询对应日志条目，以返回的引用核对编号。每轮也复查之前各轮的编号。
- 第三轮登记验收版的第二种说法，核对同一单元的两个独立来源，再用其结果继续查到“回执只读”。用陌生问法浏览、选定和确认候选，再改变条件，检查旧选择失效。为同一条件加入冲突结果后检查弃答。

从已安装目录复测的数据如下。Token 数为 DSH 对当前上下文的估算。找回次数按当轮复查的不同部件编号计算。

| 轮次 | 压缩前 | 压缩后 | 已离开摘要并按原文找回 |
| --- | ---: | ---: | ---: |
| 1 | 1114 | 447 | 1/1 |
| 2 | 1568 | 503 | 2/2 |
| 3 | 1652 | 593 | 3/3 |

最后只给本地模型三条原文引用的内容，它答对了验收并行数、回执只读要求，以及第一轮指定条目的完整部件编号。另一次 `memory_index` 调用从具有明确条件和结果的句子中抽取了一个碎片。通用历史问答的正确率和模型自主调用工具的成功率需单独评测。[机器可读结果](../validation/guided-compaction.json) · [测试脚本](../scripts/test-fragment-compaction.cjs)

最初只放入一个显眼的校验编号时，模型将其全文写进摘要。后续改用正常装配日志中的编号，并在测试中直接断言编号已消失。一次尝试达到了 1024 个输出 token 的摘要上限，DSH 拒绝提交残缺摘要；复现脚本给合成会话预留 2048 个输出 token。程序在摘要未完成、当前上下文仍含抽查值、来源对不上或读回值错误时报告失败。

先安装本地碎片模型，运行支持 Chat Completions 的本机模型服务，然后在仓库根目录执行下列命令。端口、模型别名和桌面程序路径按本机设置。可将环境变量 `FRAGMENT_TEST_PLUGIN` 设为已安装的 `dsh-conversation-memory` 目录，验证当前安装。

```powershell
$env:DSH_EXE = 'D:\Apps\DeepSeek Harness\DeepSeek Harness.exe'
$env:FRAGMENT_TEST_URL = 'http://127.0.0.1:8080/v1/chat/completions'
$env:FRAGMENT_TEST_MODEL = 'fragment-test'
node scripts/test-fragment-compaction.cjs
```

## 0.5.0 碎片归档与桌面兼容性

在 Windows 上运行 `node scripts/test.cjs`。设置 `DSH_RUNTIME_NATIVE_TEST=1`、`DSH_EXE` 为桌面程序路径，会一并执行四项原生测试。在 0.2.1-rc.5 与 0.2.2-rc.5 上分别通过 374/374，0.2.3-alpha.2 的四项原生测试也全部通过。覆盖了三个预设的安装、两个插件的登记与开关、原生 Session、模型路由请求头、压缩边界、归档回读和逐字节配置回滚。模型请求使用桩。

存储回归覆盖 schema 1 中不连续的消息序号及旧引用、同文不同角色、重新打开和损坏后整笔回滚。工具回归覆盖分页、按角色筛选、局部词项建议、选中引用回读、会话隔离，以及浏览结果不会归档为新的原话。候选按 SQLite 词项相关性排序；本版没有在自然语言改写任务上测量模型级语义召回率。

## 冻结运行版本 0.4.2

真实路由：`opencode-go/deepseek-v4.1-flash`。从空会话启动 DSH 原生完整流程，16 轮真实 followup，113 个请求（46 主请求、67 辅助请求），不是把历史拼成一次输入。

覆盖用户中途纠正后纯“继续”、跨报告末尾/开头依赖、相同失败条件下不重复执行、外部条件真实变化后合法重试、自动原生压力摘要和压缩后仅通过 memory_search/read 回读原文。46 次模型去重尝试全部结束，无去重超时；最长约 145 秒。该受控任务没有重复犯错。实际记忆包峰值 5796 码点，没有超过 6000。

**原始严格结果为 false，未覆盖或改写**：一次既有 semantic-pruner 的 180 秒整轮预算到期，取消一个未完成候选的判断。通过时间线、冻结实现和逐字节 SHA-256 独立验证该候选 49930 码点全文原样进入原生摘要并保留在库中；native 摘要随后正常完成。取消不是成功模型流；归因是源码和时序推断，没有直接记录 AbortSignal.reason。

允许恰好这一项原有预算边界后的任务/记忆验证通过，其余异常不豁免。不能用该结果声称“所有辅助请求成功”。live 未触发可选 memory-index 和多批 reduce，对这两项只有离线覆盖。

原开发回归 292/292，包括一个原生 Session 集成测试。第一次分发目录检查有一条旧测试断言 2048/8192 不一致，已在长测结束后只同步测试文件、通过17项相关检查，运行模块未修改或重载。旧失败记录本地保留；公开包不含机器路径、真实会话、隐藏推理、数据库或原始压力材料。`validation/summary.json` 是**公开概要**，不是原始轨迹。`validation/runtime-hashes.json` 记录与冻结运行源一致的插件运行模块哈希。

## 不能据此保证的事情

- 任意模型、任务长度或工具格式都能成功；模型仍会有注意力、漏选和判断错误。
- 超大工具结果永远零丢失。DSH spill 可能先生成预览，临时文件遵循原生保留期限。
- 关键实体检测可以识别所有实体或所有语义约束。
- 全部上下文都被 6000 码点约束。这个上限只属于本插件 provider，其他 provider 和原生保留历史另计。
- 已验证所有平台、DSH 新版本或第三方 compaction backend。自动安装仅支持 Windows 0.2.1-rc.2。

失败时查看 memory_status 和回读原文，不把摘要或已批准但预算未准入的候选当作已完整查阅。
