# Token 使用说明

适用范围：DSH Conversation Memory 0.4.2-cachefix.5，默认 `stable-prefix` 桌面配置。说明中的“额外请求”指在正常对话、原生 DSH 摘要之外，插件直接发起的模型辅助请求。

## 会产生额外模型 Token 的环节

| 环节 | 触发方式 | 模型请求与用量 |
|---|---|---|
| 工具结果语义筛选 | 原生压缩流程处理超过阈值的候选工具结果 | 分块把候选原文、只读背景和筛选规则发送给当前会话模型，返回片段编号；输入、输出和服务商报告的推理用量均需考虑 |
| 历史记忆去重 | 原生压缩后的记忆维护需要整理旧记忆快照时 | 使用当前会话模型判断保留、去重与替换；可能分批或校验重试，每个已发送请求均可能产生用量 |
| `memory_index` 语义索引 | 用户或主模型按需调用该工具 | 对匹配的原文块提取语义索引；默认每次最多 2 次模型调用，可将 `maxCalls` 设为 1–4。无可处理来源时可以不发起调用 |

这些辅助请求沿用当前会话的 provider/model，使用同一路由的 API 或套餐额度。没有额外子 Agent，不代表没有模型请求。后台归档不会自动为全部历史逐条生成语义索引。

## 在本地执行的环节

原文归档、SQLite 数据库与全文索引写入、哈希和引用校验、多路关键词检索、原文读取及状态检查本身不调用模型。桌面端的 `memory_search` 与自动召回使用本地查询，查询分支数不等于模型/API 请求数。

`memory_search`、`memory_read`、`memory_status` 的本地执行没有额外辅助模型请求，但整次工具交互仍可能产生主模型 Token：

- 主模型生成工具名和参数，属于模型输出。
- 搜索结果、原文正文、索引进度及状态结果进入后续主请求，属于输入上下文。
- 插件固定规则、工具定义和自动召回的记忆包，随主请求发送时也属于输入上下文。
- 主模型阅读证据后生成回答、推理或下一次工具调用，继续使用该模型的正常额度。

SQLite 全文索引属于本地操作；`memory_index` 调用模型建立的语义索引属于额外模型消耗，两者应分别理解。

## DSH 原有模型用量

正常对话和原生 Basic 压缩摘要本来就会调用模型。插件保留这条原生流程；摘要请求的输入和输出仍有用量，不应把所有压缩开销都算作插件新增请求，也不能把它们当作免费操作。

## 预算、缓存与失败请求

- 8192、5159 和 6000 等正文预算使用 Unicode 码点计数，并非 Token 数；具体 Token 数由模型分词决定。
- `maxTokens` 是输出上限，不是固定消耗量；输入原文、规则和背景同样需要计入。部分模型将推理 Token 计入输出用量，汇总时不要重复相加。
- KV 缓存命中仍可能报告缓存读取用量；实际计费或套餐扣量以服务商的 usage 和规则为准，缓存命中率不等于免费比例。
- 请求超时、取消、模型输出校验失败或随后回退时，服务商已经处理的部分仍可能产生用量；未取得 usage 的失败请求不能直接按零 Token 统计。重试也可能增加用量。
- 具体消耗取决于原文长度、片段数量、模型行为和触发频率，不能仅凭最终记忆包的长度判断总消耗。实测中分别列出了主请求和辅助请求，见 [Go Token 与 KV 报告](GO_PRESSURE_CACHEFIX5.md)。

## 独立库调用的可选模型重排

上面的本地检索说明针对配套 DSH 桌面工具。直接使用独立 `library/` API 时，如果提供了模型并启用 `useModel:true`，`recall` 或 `buildContext` 在存在候选时还可调用 `memory-rerank` 进行模型重排，产生额外 Token。当前桌面检索路径显式使用 `useModel:false`，没有启用这类重排请求。
