使用前请了解：本插件可能额外耗费模型 Token

插件沿用你在 DSH 中配置的模型/API。没有单独的子 Agent，不代表没有额外模型请求。以下情况可能增加 Token 或套餐额度消耗：

1. 自动筛选超长工具结果
原生压缩流程处理候选工具结果时，插件可能调用当前模型选择需要保留的原文。输入包含原文、背景和筛选规则，模型输出也有用量。

2. 压缩后整理历史记忆
原生压缩后需要去重、选择和替换旧记忆快照时，可能发起模型辅助请求。

3. 按需建立语义索引
主模型或用户调用 memory_index 时，插件可能用模型处理匹配的原文块。它不会自动为全部历史逐条调用模型；无可处理内容时也可能不发起请求。

4. 长内容分块、校验重试或重新处理
一次操作可能拆成多次辅助请求。每块发送的正文、规则、背景以及每次重试都可能增加输入和输出 Token；不能只按最终保留的文字长度估算总用量。

5. 请求失败、超时、取消，或结果未被采用
只要服务商已经处理了请求，已发生的用量就可能计入额度。模型结果未通过校验、程序保留原文或回退到原生流程，不代表前面的请求是零消耗。没有返回 usage 的失败请求也不能直接按零 Token 处理。

6. 主模型发起工具调用、阅读回读结果
memory_search、memory_read、memory_status 的本地处理不额外调用模型，但主模型生成工具调用和参数属于输出；工具结果、插件规则、工具定义、召回记忆随请求发送后属于输入上下文。

7. DSH 原生摘要与正常对话
这些是 DSH 原有的模型请求，本身也使用 Token。原生摘要与插件辅助整理可能分别产生用量。

8. KV 缓存命中
缓存命中不等于零 Token。服务商仍可能报告缓存读取用量，实际计费或套餐扣量以服务商 usage 和规则为准。

本地归档、SQLite 数据库与全文索引写入、关键词多路检索、原文读取、哈希和引用校验本身不消耗模型 Token，但会使用本机 CPU 和磁盘。

实际消耗取决于模型、原文长度、分块数量和触发频率；插件不保证所有任务都减少总 Token 或费用。
